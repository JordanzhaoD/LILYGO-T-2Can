# Legacy NAG beta.14 Vehicle Analysis

> The direction-evidence hold below is superseded for the target 2019 Model X
> on vehicle software 2026.2.11 by `4.3.0-beta.15`. Beta.15 intentionally uses
> the upstream beta.7 directionless mean-reverting random walk without `0x129`.

## Scope

This report analyzes vehicle captures `can_recording (89).csv` through
`can_recording (93).csv` against:

- local `4.3.0-beta.14` Legacy Continuous Absolute v4;
- upstream `hypery11/flipper-tesla-fsd@v2.16-beta.8`;
- the earlier beta.12 vehicle captures 87 and 88.

The beta.14 build only changed recorder allocation. Its active Legacy NAG
behavior is the same as beta.13.

## Capture Summary

All five recordings cover approximately 120 seconds and contain the active
logical Bus 2 stream.

| Capture | 0x370 RX | 0x370 TX | TX/RX | TX handsOnLevel | 0x129 | 0x5D9 |
| --- | ---: | ---: | ---: | --- | ---: | ---: |
| 89 | 2,367 | 2,291 | 96.8% | 0 only | 0 | 1,094 |
| 90 | 2,561 | 2,526 | 98.6% | 0 only | 0 | 1,094 |
| 91 | 2,814 | 2,489 | 88.5% | 0: 2,487; 1: 2 | 0 | 867 |
| 92 | 2,861 | 2,788 | 97.4% | 0 only | 0 | 994 |
| 93 | 2,122 | 1,973 | 93.0% | 0 only | 0 | 950 |

Every TX frame could be paired with the immediately preceding native RX frame
within 100 ms. In every pair, byte 4 was identical. Capture 91's two level-1
TX frames therefore preserve native level-1 input; they are not generated by
the firmware. All checked TX checksums are valid and the median TX interval is
40 ms.

Conclusion: the beta.13 native-byte-4 correction is working. Coverage,
counter generation, checksum generation, and handsOnLevel preservation are not
the remaining primary failure.

## DAS State-3 Timing

`DAS_handsOnState` is decoded from `0x399` byte 5 bits 5:2. Durations have the
resolution of the received `0x399` samples.

| Capture | State-3 durations | State-3 start intervals |
| --- | --- | --- |
| 89 | 1.46, 3.54, 3.72 s | 48.02, 52.51 s |
| 90 | 7.11, 6.31, 2.37 s | 54.77, 57.35 s |
| 91 | 2.00, 2.48 s | 102.14 s |
| 92 | 3.34, 3.00 s | 54.33 s |
| 93 | 1.21, 2.14 s | 54.33 s |

The median state-3 duration is about 2.74 seconds. The usual recurrence period
is about 54.33 seconds; capture 91's 102.14-second interval is an outlier and is
not enough to claim stable suppression.

Beta.12 captures 87 and 88 had state-3 durations of 8.45, 6.15, 10.22, and
9.78 seconds. Preserving native handsOnLevel therefore shortened most warning
episodes, but it did not stop the warning ladder from recurring.

## Torque-Shape Finding

The current local engine uses `boundedWave()`:

- state 2: up to +/-1.2 Nm, with polarity switched every 1.2 seconds;
- state 3 or higher: up to +/-1.8 Nm, with polarity switched every 0.8 seconds.

The captures prove that this behavior reaches the bus. During every state-3
episode the TX frames repeatedly alternate between positive and negative
torque. Positive and negative frame counts are close to equal, and the average
over the episode remains near zero. Examples:

| Capture/episode | Positive TX | Negative TX | Mean torque |
| --- | ---: | ---: | ---: |
| 90, 3.22-10.34 s | 78 | 85 | -0.03 Nm |
| 90, 58.00-64.31 s | 71 | 70 | -0.02 Nm |
| 92, 34.86-38.20 s | 37 | 43 | -0.07 Nm |
| 93, 75.53-77.67 s | 22 | 16 | +0.16 Nm |

This is the main evidence-backed mismatch with upstream Mode-C. A
direction-sensitive EPAS/DAS integrator can cancel alternating torque over its
attention window even though individual frames reach +/-1.8 Nm.

Increasing TX density is not justified. The existing path already overlays
approximately one frame per native frame in most captures.

## Upstream v2.16-beta.8 Alignment

The upstream release describes an experimental demand-state machine:

- AP must be active;
- states 0, 8, and 15 do not transmit;
- state 1 holds the last output for 500 ms, then stops;
- state 2 waits 2 seconds, then uses a one-sided 0.5-2.0 Nm random walk;
- states 3, 4, and 5 wait 1 second, ramp for 500 ms, then hold 2.1 Nm;
- torque polarity is opposite the native `0x129` steering angle;
- output uses the native frame, counter+1, and additive checksum.

Only the state-machine shape, delayed entry, smooth exit, counter, and checksum
contracts can be adopted directly. Three upstream details must not be copied:

1. Beta.8 derives handsOnLevel from synthetic torque. Later upstream vehicle
   evidence revoked this behavior. The local implementation must preserve the
   complete native byte 4.
2. Upstream uses raw torque zero 2048. The local vehicle-established zero is
   2050.
3. Upstream reaches 2.1 Nm. The current local validated boundary is +/-1.8 Nm.

## Missing Direction Evidence

All five captures contain zero `0x129` frames on both recorded controllers.
The recorder filter already admits `0x129`, so this is not a CSV filter error.
It means the current dual-CAN tap does not expose that native signal.

`0x488` is present on logical Bus 2 at high rate, but it is a DAS steering
request, not a validated replacement for the physical steering-angle sensor.
It must not be used as the sign source for active EPAS torque without a paired
capture proving its sign relationship.

`0x5D9` is present, but no verified DBC bit layout for
`DAS_LC_handsOnReason` is available in the supplied references. Its payload is
multiplexed and changes in many bytes around state-3 transitions. No single
field can be attributed to hands-on reason from these captures alone.

## Decision

Do not enable the upstream steering-angle-opposed model yet. The data supports
replacing the alternating wave with a one-sided state machine in principle,
but does not establish which side is correct on this vehicle.

The next active revision should remain blocked until one of these conditions is
met:

1. native `0x129`, `0x370`, and `0x399` are captured together from the correct
   physical buses; or
2. a controlled left/right steering capture establishes and documents a
   validated alternative angle source and sign convention.

## Next Vehicle Capture

Use Service Mode CAN Port information or an external dual-channel logger to
locate the bus carrying `0x129`. Record the following IDs together:

```text
129,370,399,488,5D9
```

Perform a stationary or low-risk controlled capture with Legacy NAG disabled:

1. wheel near center for 10 seconds;
2. hold a small left steering angle for 10 seconds;
3. return to center for 10 seconds;
4. hold a small right steering angle for 10 seconds;
5. repeat once while clearly noting the timestamps.

Acceptance evidence is a stable `0x129` sign change that can be correlated with
native `0x370` torque and the known physical wheel direction. Only after that
evidence should a default-off Mode-C trial use a one-sided torque opposite the
validated angle, preserve native byte 4, keep the 2050 zero, and retain the
local +/-1.8 Nm limit.
