# Legacy NAG beta.17 实车数据分析

## 测试结论

- 车辆：2019 Model X，软件 2026.2.11。
- 固件功能、Legacy FSD 激活和智能速度偏移运行正常。
- 调换车辆侧两路 CAN 接线后，Legacy 相关帧稳定出现在固件 CAN1。
- `0x370` Mode-C 注入按代码设计运行，但没有消除 NAG。
- 本次数据不支持继续增加扭矩或发送密度；该方向不能被视为有效或安全的
  NAG 解决方案。

## 输入文件

- `can_recording (97).csv`
- `can_recording (98).csv`
- `can_recording (99).csv`
- `can_recording (100).csv`

`98` 和 `99` 的 SHA256 完全相同，属于同一份数据的重复文件，因此只有
三次独立记录。

## 总线拓扑证据

换线后，所有 Legacy 主路径流量均位于记录器 `bus=1`：

- `0x370` EPAS RX/TX：CAN1
- `0x399` DAS 状态：CAN1
- `0x488` DAS 转向请求：CAN1
- `0x3EE` Legacy FSD RX/TX：CAN1
- `0x3FD` 少量流量：CAN2

这证明当前 2019 Model X 实车接法下，承载 Legacy 激活、EPAS 和 DAS 状态的
车辆总线必须接入 T-2CAN CAN1/TWAI。该结论是车型和线束位置相关的实测映射，
不能直接推广成所有 Tesla X197/X179 的统一针脚定义。

## 关键统计

| Capture | 时长 | 0x370 RX/TX | TX 覆盖 | 0x488 RX | state 3 | state 3 间隔 |
|---|---:|---:|---:|---:|---:|---:|
| 97 | 120.0 s | 2564 / 1427 | 55.7% | 5100 | 1 次 | - |
| 98/99 | 29.6 s | 565 / 189 | 33.5% | 1273 | 1 次 | - |
| 100 | 120.0 s | 2489 / 1696 | 68.1% | 4566 | 3 次 | 34.1 s、27.3 s |

所有 TX `0x370` 均满足：

- additive checksum：100% 正确；
- TX counter = 最近原生 RX counter + 1：100%；
- byte 4 与原生帧一致：100%；
- bytes 0/1/5 与原生帧一致：100%；
- TX `handsOnLevel` 全部保持原生 level 0；
- 有明确 `0x488` 转角方向的样本中，反方向扭矩比例为 94.7%-100%。

这排除了接线错误、checksum 错误、counter 错误、字段破坏和 Mode-C 未运行。

## NAG 未消除的直接证据

Capture 100 在持续发送合法 `0x370` TX 的情况下，DAS hands state 3 仍在
38.486 s、72.630 s、99.925 s 出现，复发间隔只有 34.144 s 和 27.295 s。
这与此前未成功版本处于同一数量级，没有形成稳定的注意力计时器复位。

车辆进入 hands state 1 时，当前引擎按设计停止：

- Capture 97：state 1 下 TX 覆盖 4.1%；
- Capture 98/99：state 1 下 TX 覆盖 0.7%；
- Capture 100：state 1 下 TX 覆盖 6.4%。

但在 state 2 和 state 3 已经存在大量、格式正确且方向正确的 TX，车辆仍进入
后续提醒。因此“只补 state 1 覆盖”不能证明会解决问题。

## 根因判断

最符合数据的解释是：该版本 Model X 的驾驶员注意力状态机不把外部总线上
竞争发送的合成 `0x370` torque 字段当作可信的人手输入。车辆可能使用 EPAS
内部扭矩传感器、原生 ECU 来源身份、其他未公开信号或多信号一致性检查。

`0x488` 是 DAS 请求转角，不是驾驶员施加在方向盘上的实际扭矩。用它反向生成
EPAS 扭矩可以构造格式一致的 CAN 帧，但不能证明有人手输入，数据已显示车辆不
接受这种替代关系。

## 解决建议

1. 保留 beta.17 已验证稳定的 Legacy `0x3EE` FSD 激活和智能速度偏移。
2. 将 Legacy `0x370` NAG 功能保持默认关闭，并标记为该车型实测无效。
3. 不继续提高扭矩、持续时间或覆盖率。`0x370` 是 EPAS 状态帧，与原生 ECU
   竞争 counter 和状态语义存在转向及车身控制故障风险。
4. 后续研究仅采用只读方式，采集真实驾驶员施力前后原生 `0x370`、DAS 状态和
   可能的实际转向扭矩信号，确认车辆真正使用的注意力输入。
5. 车辆使用层面的可靠方案仍是遵循原车驾驶员监控和方向盘提示，不应依赖
   合成 EPAS 帧绕过注意力检测。

## 音量滚轮 / 0x3C2 路径评估

四份 beta.17 记录中，十进制 ID 962（`0x3C2`）在 CAN1/CAN2 的 RX 和 TX
计数全部为零。记录器默认过滤已包含 `3C2`，因此不是 CSV 过滤遗漏。

当前 Scroll DND 实现要求先收到车辆原生、空闲的 `0x3C2 mux1` 基帧，并且
基帧年龄不超过 1000 ms；随后才允许复用原生 payload 执行有界滚轮动作。
在本次数据下，控制器只能停在 `no_native_mux1`，不能形成可验证的 TX。

滚轮动作是否能清除这台车的 NAG 仍属未知：

- `0x399` 已提供明确的提醒触发状态；
- 但当前两路接线均没有暴露 `0x3C2`；
- 2019 Model X 可能使用其他方向盘开关帧 ID，或该帧位于当前连接器未暴露的
  第三条车身/LIN 网关路径；
- 没有原生帧时，无法确认 mux、counter、checksum 和车辆是否接受该动作。

下一步只能先做只读识别：车辆静止时开始全 ID 录制，依次执行音量上、回中、
音量下、回中，并在 10-15 秒后手动停止。对两路 CAN 分别做前后差分，寻找与
动作严格同步的帧。找到原生候选帧并确认字段后，才能评估滚轮路径；不能使用
固定模板合成 `0x3C2`。
