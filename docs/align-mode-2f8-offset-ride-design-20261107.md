# 对齐模式(A3)— 0x2F8 偏移骑载 + 0x3EE 脉冲化 设计定案

日期:2026-11-07 ｜ 决策:Jordan 裁定 A3(终局方案)
输入:sess_106/107/108(固件 438b86f 实车三段)+ tesla-fsd-controller 源码对照

## 一、为什么方案 A(438b86f)没治好闪烁

方案 A 治的是"我们写入值自身锯齿"——今晨数据证明它成功了(板写 b3
51 秒恒定 E4,0x2F8 疯翻 96% 被防抖墙拒收),**但闪烁依旧** → 病根不在值,
在结构:**总线上存在两个 0x3EE 写入者长期打架**。

决定性证据(sess_108):该段板写帧与原生帧偏移字段完全相同(b3 都=D0、
pct 都=0),只剩 bit46(激活位)与源标记不同——**仍然在闪**。
且 FSD 图标与速度数字一起闪 → 两处 UI 状态由同一股 0x3EE 数据流驱动,
双流交替 = 双处闪烁。原生流"2-3 帧@1Hz 突发 + 3-4s 静默"的节奏
= Jordan 观测的 3-4s 跳变周期。

## 二、对照项目为什么不闪(tesla-fsd-controller, Legacy 模式)

它是**串行串联**(帧穿过它),改原生帧再转发 → 仪表永远只听到一个声音。
且它 Legacy 模式**从不写 0x3EE 的 b3**——偏移写进 0x2F8 data[5]
`UI_userSpeedOffset`(bits0-5 = kph+30,bits6-7 保留,bit7=单位)。
今晨数据实锤本车原生 0x2F8 在 GPS 有效帧上就带着 +10 用户偏移、
编码一致 → **该通道在本车活着,可直接使用**。

## 三、本设计(旁挂拓扑的 A3 适配)

我们是旁挂节点,堵不住原生帧 → 不追求"单流",追求**停止在 0x3EE 上
制造第二个声音**,把偏移挪到 0x2F8 的用户偏移字段上**纯骑原生帧**:

1. **0x2F8 偏移骑载(新)**:每收到一帧原生 0x2F8(~7Hz),门链开放时
   重发一份镜像帧,仅改 data[5] = (原值&0xC0) | ((offsetKph+30)&0x3F)。
   其余 7 字节逐字节等于原生。**永不自由起帧**(原生 7Hz 无饥饿可能,
   也维持"只读遥测 ID 不凭空说话"的纪律)。偏移值来自方案 A 已稳定的
   引擎输出(LegacyLimitStabilizer 管线不变)。
2. **0x3EE 脉冲化(新)**:对齐模式下 0x3EE 只在激活沿(triggered 上升沿)
   后一个有界窗口(5s)内骑行原生 mux0 写 bit46(+档位画像位);
   窗口外 0x3EE 完全静默(mux0/mux1 骑行与保活全部停止——原生 mux1
   本来就带 bit19=0,我们的镜像纯冗余)。
3. **配置开关**:NVS 键 `lfsd_aln`(默认关=现行对抗模式,行为零变化),
   /config `align=1` 开启,/status 暴露 `alignMode` + 骑载计数。
   **应急回退 = 远程关掉开关,即刻回到现行行为。**

## 四、TX 安全摘要(0x2F8 首次开口,依三重摘要制)

1. **发什么**:只重发"刚收到的原生 0x2F8"的单字段修改副本,永不原创、
   永不保活自由帧;只动 data[5] 低 6 位,单位位/保留位原样。
   节奏=原生节奏(~7Hz),总线负载 ~7 帧/s 可忽略。
2. **风险**:成为 0x2F8 的第二写入者(若仪表对该 ID 也是逐帧双源打架,
   理论上可能把闪烁搬到速度遥测上——明日实车即见分晓;仪表对 0x2F8 的
   消费是"最新帧渲染"型(GPS 速度显示),双源冲突概率远低于 0x3EE 的
   状态锁存型);0x2F8 上还有 DAS 消费者的话可能读到我们的偏移值——
   偏移本来就是给全车的用户设置,语义正确。
3. **回退**:`lfsd_aln` 开关远程秒回现行模式;不发自由帧=原生帧丢失时
   我们自动哑火(fail-closed)。

## 五、验证计划

- 台架:native 测试钉死骑载编码/单位位保留/门链/脉冲窗口/现行模式零变化。
- 实车(明晨):开关开,三看——①FSD 图标是否稳(脉冲后静默期);
  ②速度数字是否稳且偏移生效(骑载生效=显示速度=真速+我们的偏移);
  ③抓录里 0x2F8 应出现 R/T 成对(~7Hz)、0x3EE 应只剩 5s 脉冲窗内 T。
- 判据:图标数字双稳 = A3 成立;图标稳但偏移丢 = 骑载字段不对,查编码;
  仍闪 = 0x2F8 也是锁存型双源 → 退回研究真·一次性状态写入通道。

## 六、非目标

- 不动方案 A 的防抖管线(继续工作);
- 不做 0x438 视觉限速滑杆(controller 有,本车未验证语义);
- UI 不加开关页(简约,curl/配置端点可操作,需要时下版再加)。

## 七、A3.1 修正（2026-11-08，P0 田野事故 sess_109/110）

**事故**：A3 上板次日实车 FSD 无法激活。两段抓录（77s）0x3EE 我方 TX=0，
mux0 全程冻结 `00 00 00 D0 20 00 02 80`，bit46 全程缺席。

**根因**（四条证据闭合）：
1. A3 脉冲只认 `fsdTriggered` **上升沿**（handlers.h 原 1033 行）；
2. 田野配置 fsdActivation=ON → `forceActivateRuntime` 常高 → 上升沿**每次开机至多一条**，
   5s 窗在开机瞬间烧完，之后 0x3EE 永久沉默；
3. 即便 forced=OFF：触发源 `isFSDSelectedInUI`（mux0 b4 bit6）在**全部 31 个历史会话
   （含多次 FSD 成功激活时段）从未置位**——tesla-controller 架构的该前提在本车不成立；
4. bit46 在本车唯一来源=我方 TX（历史所有 bit46>0 会话全为我方帧）→ 脉冲不开
   = 激活分类器在 state3 识别窗口内永远看不到 bit46 = FSD 无法激活。

**修正**：脉冲触发源改为车自身真信号——**0x399 进入 state 3（识别窗口）逐帧续期**
`alignPulseUntilMs = nowMs + 5000`；离开 state3 自然衰减（识别窗口 + 5s 尾巴）；
state 6（FSD 活跃巡航）不续期=稳态驾驶保持静默（A3 防闪目标不破）；
失败重试（回落 state2 再进 3）自动重新武装。原 `alignPrevTriggered` 闩锁删除。

**可观测性**：/status `legacySmartSpeed` 新增 `alignPulseOpen` / `alignPulseUntilMs` /
`alignApState`——田野判读不再依赖离线 CSV。

**紧急止损**（本修正 OTA 前）：`POST /config?align=0` 远程回退现行模式，立即恢复 FSD。

**测试**：native 新增 4（田野回归=forced 常高下 state3 武装/重试再武装/续期/state6 静默）
+ 改写 2（原 forced 边沿武装改为 state3 武装）+ 合约钉（921 处武装源、闩锁移除、
status 三字段）。native 矩阵 25 env 795 用例、pytest 495+754、双 ESP 构建全绿。

## 八、A3.2（2026-11-08 晚，sess_111/112）：选择性静默整体放弃——全程骑载

### 田野判决（两段新证据 + Jordan 反馈）

**sess_111（不开 AP，59s）**：0x399 全程只在 state 1/2 徘徊，**state 3 从未出现**
→ A3.1 脉冲窗永不开 → 0x3EE TX=0。症状：无 SR 渲染、速度偏移无显示。
关键反证：0x2F8 镜像骑载 36/36 全对、偏移位全程在场（b5 E8→EE）——**数据在发，
车不显示**。结论：IC 只在 SR 渲染（bit46 语境）里显示偏移；两个症状同一根。

**sess_112（开 AP，58s）**：state 3 出现 0.2s（3.8s）→ 窗开 → 8 帧 0x3EE（4.0-8.7s）
→ FSD 激活成功进 state 6 → 窗烧完静默。激活路径 ✓。但随后 Jordan 反馈
"速度策略四档完全无效"。

### 机制复核（dash_legacy_smart_offset.h 实锤）

- **四档 = Custom 模式四段百分比**（customPctLow/Mid/High/VeryHigh；Auto 也有分段表）；
- 头文件原话：*"The verified Legacy path **reads 0x2F8 but writes its request on
  0x3EE mux 0**"*——偏移请求（kph→b3、0x03 旗标→b5、百分比档→b7）的**验证过的
  唯一写入通道是 0x3EE**。A3 把偏移搬到 0x2F8 data[5] 是未验证假设，田野判死；
- keep-alive 注释原话：*"the car-side consumer **ages out** bit46 + the speed
  offset"*——消费端会老化，静默=饿死。state 6 静默恰恰在最需要的时候（FSD 按
  限速+偏移巡航）杀死四档策略。

### A3.2 修正（触发反转的终局：去掉一切 0x399 耦合）

| 通道 | A3/A3.1 | A3.2 |
|---|---|---|
| 0x3EE mux0 bit46 | 只在 state3 窗内 | **全程骑载（上车即开，含 state 6）** |
| 0x3EE mux0 偏移 b3/b5/b7 | 搬去 0x2F8（失效） | **写回验证过的通道** |
| 0x3EE mux1 | 静默 | 静默（原生已带 bit19=0） |
| 0x2F8 偏移骑载 | 有 | 保留（无害第二副本） |
| 0x399 耦合 | state3 开门/state6 关门 | **完全删除**（kAlignPulseMs、alignPulseUntilMs、921 武装块全拆） |

/state 的 alignPulseOpen/alignPulseUntilMs 随窗一起删除，alignApState 保留作田野语境。

**已知代价**：state 6 里恢复骑载=与车机自写者双写 b3/b7，闪烁有回归风险（A3 的初衷）。
功能优先（Jordan 判决）；保留的减闪手段=值同步骑载+原生静默桥接+平滑引擎。

**测试**：native 改写为 9 个 A3.2 语义用例（boot 即骑载零 0x399/state1-2 全程骑载/
state3 窗内 bit46 在场/state6 持续骑载+keep-alive 桥接/偏移-only 骑载/bit46+偏移
同帧四件套/mux1 静默/0x2F8 双骑）+ 合约钉反转（m0 无静默门、无 `speedAllowed &&
!alignMode`、921 块零 align 耦合、status 无窗字段）。RED=5 失败精确复刻田野
（"Expected N Was 0"）。门禁：native 25 env 769 用例、pytest 495+754、双 ESP 构建全绿。

**田野判读（下次开车三看）**：①上车即 SR 渲染+偏移显示（不开 AP）；②FSD 激活
（开 AP）；③FSD 行驶中四档偏移生效 + 观察闪烁是否回归。
