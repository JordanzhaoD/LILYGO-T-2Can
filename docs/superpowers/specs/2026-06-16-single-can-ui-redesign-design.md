## 1. 背景与目标

微雪单 CAN standalone V1.0 的 Web UI 全部集中在单文件 `include/web/mcp2515_dashboard_ui.src.h`（3779 行，经 gzip 存储进固件）。该 UI 存在两类问题：

1. **4 个具体缺陷**：手机底部导航缺模块、驾驶中心多余的 CAN2 块、插件/AP 注入块风格脱节、首页底部 3 个无意义展示块。
2. **整体风格不统一**：「驾驶状态中心」「车辆态势」是丰富的驾驶舱玻璃拟态风格（氛围层、状态胶囊、图标三件套、中文），但「插件管理」「AP 注入安全」等板块是英文扁平工具网格，二者割裂。

**目标**：修复 4 个缺陷，并把全部板块统一到驾驶舱玻璃拟态风格。

**执行策略（已确认：设计系统优先）**：先从驾驶中心抽取视觉基因成一套 token + 组件基底，再逐板块套用。一致性最高，单文件 + 已有模板使成本可控。

---

## 2. 设计语言基准

以「驾驶状态中心 + 车辆态势」为全板块模板。特征：

- 氛围层背景（radial gradient + 深色底）
- 状态胶囊（cockpit-chip：ok / warn / 默认）
- 图标 + 主值 + 说明三件套（cockpit-metric：lbl / val / hint）
- 双列布局（主区 + 车辆区）
- 全中文文案 + emoji 图标

## 4. 问题 1：手机底部导航补全

### 现状
standalone 手机底部 `#mob-tabs`（3749-3754 行）仅 4 个标签：首页 / 驾驶 / 插件 / 网络。缺「更多」，手机端无法访问全部模块。

### 设计
新 5 标签替换旧 4 标签：

| 标签 | 跳转 | 说明 |
|------|------|------|
| 驾驶 | 驾驶状态中心（pg-overview） | 含现场 FSD 遥控（原"首页"现场遥控融入驾驶中心） |
| 硬件 | 硬件模式（pg-hardware） | 含插件管理（原"插件"标签内容并入此页） |
| 速度 | 速度策略（pg-speed） | |
| 网络 | 网络设置（pg-network） | |
| 更多 | 弹出面板 | 驾驶风格 · FSD 防护 · OTA 升级 · CAN 诊断 |

- 「更多」是收纳容器，点开弹出面板列出剩余模块入口；每个入口进对应**完整驾驶舱页面**（不再是当前简陋卡片）。
- 单 CAN 隐藏项（CAN2 / 灯光特技 / 自动换挡）不出现。

### 涉及
- 重写 `#mob-tabs`（5 标签）+ 新增「更多」弹出面板（standalone 版，复用现有 `#mob-more` 结构但解除 `data-single-hide`）。
- `showMobilePage()` / `toggleMobMore()` / `updateMobTabs()` JS 适配新标签集。
- 现场 FSD 遥控（mobile-remote，本属 pg-overview）随「驾驶」标签显示；插件管理 UI 在硬件页内（与桌面一致，桌面本就如此）。

## 5. 问题 2：驾驶中心 CAN2 → AP 激活状态

### 现状
驾驶中心 metrics 行（594-599 行）：CAN1 / **CAN2** / 帧率 / 芯片温度。单 CAN 无 CAN2，该格（`s-can2`，596 行）无意义。

### 设计
CAN2 格替换为「AP 激活」指标格，沿用三件套格式（与 CAN1 / 帧率 / 芯片温度一致，不破坏视觉节奏）：

| 状态 | 主值（val） | 说明（hint） |
|------|------------|-------------|
| 未激活 | 等待（灰） | 门控未触发 |
| 已激活 | 激活（绿） | Gate {delay}ms · 已就绪 |

- 数据源：`/status` 的 `APActive` + `apGate` + 延迟注入设定值。
- 主值与 AP 注入安全块的状态胶囊同源（同一个 `APActive` 字段）。
- **纯 UI 替换，不动后端。**

### 涉及
- 替换 596 行 `<div class="cockpit-metric">` 的 CAN2 → AP 激活（lbl / val id / hint）。
- JS：原 `s-can2` 更新逻辑改为读取 `APActive` 并更新新格。

## 7. 问题 3b：AP 注入安全重设计

### 现状
`ap-core-card`（759-768 行）：`card-h` + `grid c4`（门控 / 延迟 / AUTO-RESTORE / 来源）+ `diag-line`，状态缩在角落小标签。

### 设计（只改显示，不改安全线）
- **卡头**：🛡 AP 注入安全 + 状态胶囊（等待 AP / 已激活 / 已注入）
- **状态主区**（state-panel 风格）：大字 AP 状态（等待灰 / 激活绿）+ **Gate 计时进度条**（可视化「为什么注入要等 2 秒」）
- **注入来源**：独立 metric（Disabled / FSD-V14 / Legacy）
- **控制三件**（中文化 + 说明）：
  - AP 门控（要求 Parked / AP / Summon 后才注入）
  - 延迟注入（0 / 1s / **2s** / 3s 卡片选择，推荐 2s）
  - AP 自动恢复（重启后恢复上次 AP 配置）
- **fail-closed 安全条**：未知 / 无效 / SNA 档位默认禁止注入；AP 断开立即清零 Gate 计时。

### 安全边界（不变）
fail-closed、2s settle、AP 断开清零 = **服务端 C++ 强制**（`handlers.h` 发送路径），客户端 JS 无法绕过。重设计只把这条安全线**可视化**，不弱化、不绕过。

### 涉及
- 重写 `ap-core-card` HTML + CSS。
- Gate 进度条 JS：取延迟注入设定值 + AP active settle 计时渲染。
- 移动端 AP 控制卡片（`mob-driving-page`）同步驾驶舱化。

## 10. 非目标（YAGNI）

- **不改桌面侧边栏结构**：11 个 nav-item 不变，只做视觉拉齐。
