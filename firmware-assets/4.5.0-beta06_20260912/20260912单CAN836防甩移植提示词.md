## 侦察已确认的事实（v1.17 行号，直接用；开工时快速复核仍有效即可）
1. 单 CAN **没有 crc8J1850**（全仓库零命中）——0x045 发送基础设施缺失，是最大移植增量。
   helper 从双 CAN dash_legacy_wheel_045_dnd.h 抽出内联进协调器头；TX evidence 照
   main.cpp:505-535 的 0x249 模式（recordAttempt/recordResult + dashRecordCanFrame(f, ok?'T':'E')），
   经主 driver（TWAI）send + dashDriver->onSendFrame 计数链
2. waveshare_single_can_standalone = **纯 TWAI 单总线、无 MCP2515**（platformio.ini:11-13），
   帧 bus 恒为默认 CAN_BUS_ANY → 编译 profile **sourceBus 从 CAN_BUS_VEH 改 CAN_BUS_ANY**；
   其余标定值全部照搬不改（byte0 bits0-1/掩码 0x03/FWD=1/RWD=2/窗口 2400/cancelEvidence 1500/
   requestSeq 1000/releaseGap 100/requestApMask{2}/availableWaitTimeout 3000/
   kVehicleRefusalMs 2500——它们是车属性，不依赖设备）
3. 单 CAN dashboard 层**没有逐帧分发 switch**（双 CAN case 0x045: 挂点不存在，帧全走
   LegacyHandler::onFrame）→ observeNative045/observeDasStatus 在 main.cpp appLoop 收帧后
   **新建统一观测回调**（id 过滤，先于 handler 分发；P2 flag 直方图要求 Disabled/门控关也计数）
4. intent 计算 handlers.h:979-981 `forced || uiSelected` 与双 CAN 同款 →
   observeNative3ee 挂 0x3EE mux0 recordRx 后（:977）、gate 查询前同帧
5. sole authority：mcp2515_dashboard.h:997 dashLegacyFsdActivationAllowed 内插协调器
   active() 分支，必须在 `!apInjectionGate` 早退**之前**（beta03 框架照搬：门控关=旧直通
   合法=非 8.3.6 车正常模式；门控开+开关开=协调器唯一权威）
6. tick + setPermit 挂 mcpDashboardLoop（app_main_loop 每轮调）；permit = canActive &&
   OTA guard 允许（照 dashInjectionActive 同源），**刻意不含门控**（防 permitLost 锁死）
7. inhibitDevice3ee（Barrier A）挂 handlers.h mux0 gate 链（abortGuard 检查旁）+ mux1 路径
8. ownsStalk 保留逻辑但天然无竞争：单 CAN 滚轮 DND 是 0x3C2（additive checksum，非 J1850），
   与 0x045 无共享帧/counter
9. configure(enabled, profile, apGateOpen) 三参照搬：/config POST + NVS 键 apr_on +
   运行态重放点（找单 CAN 的 dashApplyRuntimeState 等价物；beta06 语义=同 enable+同 gate+
   字节同一 profile 且 ActiveInjection 才保留轮次，否则全重置）
10. UI：pg-defense:1384 已有 def-master-tgl(:1431)；新增 def-ap-rerequest-tgl 开关 +
    诊断网格（rrPhaseMap 全量中文映射+「车辆响应」格+lastEndedReason/autoRearms）+
    ap-gate-tgl(:961，旧 saveApGate 分散模式) 作为门控前提联动，建议顺手收拢进 FSD 防护页
