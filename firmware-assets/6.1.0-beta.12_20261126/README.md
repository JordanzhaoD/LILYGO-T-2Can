## beta.11 实车数据说明了什么

**左滚轮免打扰没发一帧，但引擎没坏。** 把你那段录制的帧原样喂给生产引擎（带真实的双引擎协调），桌面上能发出 67 帧。所以是车上某道运行时闸关着。回查全部历史录制：左滚轮的帧**最后一次在实车发出是 11-23 22:48**，从 11-24 起就一帧没发过——不是 beta.11 才坏的。

**右滚轮「偶尔有效」的真相：** 提醒分两种。短的那种约 0.5 秒自己就消失，点不点都会走；持续的那种（没人管时 5–9 秒）才是真要清的。beta.11 的「点击」对持续型 **0/3**，提醒照样走完自然时长。

**我上一版改错了形态。** beta.07 有效不是「点击」——它是**按住**：提醒持续期间每个原生滚轮帧后面都跟一帧按压，直到车把手部状态降下去（4–8 帧，0.4–0.7 秒）。beta.11 为了不弹菜单把它缩短成约 100ms 的点击，车就不认了。

## 这一版改了什么

### 1. 两个滚轮引擎去掉「车辆 OTA 标志」这道闸（按你的决定）

这个标志只能靠 0x318 帧来清除，而这辆车的总线上没有这种帧——所以它一旦置位，整段行程都是「OTA 进行中」，两个引擎一起沉默。

**范围**：只去掉两个滚轮引擎上的。FSD 激活注入和防甩程序**保留**这道闸（车辆真在升级时改激活状态风险大，你没提到它们）。

### 2. 右滚轮回到「按住」形态，但有上限

| | beta.07（6/6 清除） | beta.11（持续型 0/3） | **beta.12** |
|---|---|---|---|
| 形态 | 每个原生帧后跟一帧按压 | 按下 + 立刻松开 | **每个原生帧后跟一帧按压** |
| 上限 | 无 | 每轮 2 次 | **每轮最多 6 帧** |
| 松开帧 | 不发（车的下一帧自然松开） | 发 | **不发** |

保留 beta.11 的全部安全件：提醒须连续消失 1.5 秒才开新一轮；hands=2 不触发；提醒闪回、闸门翻转都不会重新装弹。

**已知代价（与 beta.07 相同，未解决）：按压会弹出车机中央键菜单。**

### 3. 界面直接显示是哪道闸挡着

两个滚轮的诊断表上方各加一条状态横条：

- 🟢 **运行中**
- ⚪ **开关未开启**
- 🔴 **被闸门拦截** + 具体是哪道（用中文写明，如「CAN 发送器未就绪」「Abort Guard 锁止」）
- 🔴 **连续发送失败，已自动停用**（约 0.8 秒后自恢复）

「阻断原因」那一行也从代码翻成了中文。**下次再有引擎不动，看这条横条就知道原因**，不用再猜。
