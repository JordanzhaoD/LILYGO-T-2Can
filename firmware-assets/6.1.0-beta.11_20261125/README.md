# 固件资产 6.1.0-beta.11（2026-11-25）— 右滚轮点击免打扰 · 独立审查修复

**uiBuildId**: `6.1.0-beta.11-lilygo_t2can_dual-cc5eea0b6fe0`

## 这一版是什么

beta.10 的独立代码审查抓到 **1 个严重 + 5 个重要**缺陷，全部在本版修复。
**右滚轮开关保持默认关闭时，行为与 beta.10 完全相同**——下面的内容只在打开右滚轮开关后才生效。

## 严重缺陷：没有全局发包上限

beta.10 的「每轮最多 2 次点击」只在单轮内成立。提醒状态在 2↔3 之间闪回，或任一闸门落下再抬起，都会把 2 次预算重新装满——审查复现出约 10 帧/秒的持续发包，**比 beta.08 那次事故（8.8 帧/秒）还密**。

**修法**：一轮提醒必须**连续消失满 1.5 秒**才算真正清除，之后的提醒才开新一轮。一条规则，对提醒状态、闸门、开关一视同仁。

## 点击形态变了（按你的决定）

| | beta.10 | beta.11 |
|---|---|---|
| 按下帧 | 骑原生帧，计数器 +1 | 同 |
| 松开帧 | 按下后**立即**发，计数器 **+2** | 骑**车的下一个原生帧**，计数器 +1 |
| 总线序列 | 原生、按下、松开、原生 | 原生、按下、原生、松开 |
| 按键被按住时长 | 约 0.25 ms | 约 100 ms（一个原生帧间隔） |

改的原因：+2 的松开帧抢在车自己的帧之前，总线上出现计数器**倒退**（c → c+1 → c+2 → c+1），这台设备从没发过这种形态。

**代价要说清楚**：按键被按住的时长回到了约 100ms，和 beta.07 弹菜单时的量级接近。**菜单是否还会弹，是这一版上车要回答的问题。**

## 其他修复

- **状态表 AP 状态不再显示 `AP--`**（固件之前没把这个字段发出来）
- **「阻断原因」可读了**：不会被下一拍覆盖；`episode_limit` 会一直显示到这轮结束；引擎被闸门挡住时，真实的提醒仍显示为告警，并标注「闸门拦截」
- **松开帧发送失败会被发现**：状态表的「松开」只在总线真的收下后才 +1；失败的松开帧会在下一拍重发，连续失败会解除引擎
- **运行许可只有一个写入者**：之前保存任意设置页时，会用一个更宽松的条件重新放行引擎
- **左滚轮免打扰不会再被右轮卡死**：点击后闸门落下时，右轮会立即让出节拍
- 防护页单独保存「右滚轮按压」开关现在能生效（之前只发这一个参数会被忽略）

## 关于「总开关默认关闭时两个引擎都不动」

这个问题我和独立审查各追了一遍代码，**都没有找到**让 FSD 注入总开关挡住两个滚轮引擎的路径。可以确认的是：开过一次总开关后，固件内部的旧开关状态会一直是「开」，并写进开机自启设置——所以那块板子之后每次启动其实都是开着的。

如果你在本版上、**重启后从未碰过总开关**的情况下仍能复现，请在提醒出现时抓一份 `/status`，里面这两个引擎的字段能直接指出是哪道闸。
