第二轮迭代——间距 25ms 仍被车机反向合并窗口吞掉，对齐真实换向地板

## 修复：DND 左滚轮音量漂移（第二轮，对齐真实换向地板）

- **beta04 实车结论**：音量从 4 一路掉到 1，正好 3 档 = 每警告周期
  3 对上限 × 每对净 −1——车机仍然只执行了每对里的 −1。P 档对照
  （不开 FSD 音量不掉）确认注入只发生在警告时，排除警告误判线。
- **根因翻案**：车机的反向合并窗口比任何同向脉冲地板都宽——
  25ms（真实滚轮同向脉冲地板 19-20ms + 余量）仍是错的参照系。
  车机唯一可证接受的反向转换是真实滚轮换向，段13 实测 ≥600ms。
- **修复**：`kBurstMinGapMs` 25 → 600ms；配套 `kReleaseTimeoutMs`
  300 → 1200ms（硬约束：超时必须大于间距，否则反向帧在等待中被
  超时中止、+1 搁浅在总线上，音量会变成每对 +1 向上漂）。
- **新增测试钉**：两个常量各一个 pin + 超时必须覆盖间距的不变量
  测试；全套 native 测试时间基准切换到 600ms 世界。
- **预期副作用**：DND 消警告时每对会有约 0.6 秒的音量"哒—回"
  脉冲（+1 后回落），比持续下降好得多。
- **诚实风险**：若车机窗口 >600ms，备选方案是滚轮按压帧
  （b4=00，零音量副作用），但需先实车验证按压被计为有效互动。
