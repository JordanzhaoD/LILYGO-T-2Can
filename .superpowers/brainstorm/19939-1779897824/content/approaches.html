简单 体积大

A. 单文件重写（推荐）

一个 HTML 文件包含所有 8 个页面，JS 控制显示/隐藏。与当前架构一致，后端 API 不变，只需重写前端。

CSS-in-JS templates
模板化渲染
const pages = { overview: renderOverview, ... }
function renderOverview(d) { return `...` }
sidebar.onclick → render(page)
体积小 复杂

B. JS 模板化渲染

HTML 只包含骨架和侧边栏，页面内容通过 JS 模板函数动态生成。体积更小，但代码复杂度高。

partial rewrite only
渐进式改造

重写
CSS样式
新增
sidebar JS
cards → pages (CSS class swap)
风险低 不够彻底

C. 渐进式改造

保留现有 HTML 结构，添加侧边栏导航容器，用 CSS 将现有卡片转为页面。最小改动，但布局可能不够灵活。

推荐：方案 A

为什么推荐 A

  • 与当前架构完全一致，后端 API 零改动
  • 一次性彻底重写，不背负旧代码包袱
  • minify + gzip 后体积可接受（ESP32 16MB flash）
  • 前端 JS 简单（show/hide pages），不易出 bug

主要顾虑

  • HTML 源文件会比现在大（但 gzip 后差异不大）
  • 需要完整重写 .src.h 文件
